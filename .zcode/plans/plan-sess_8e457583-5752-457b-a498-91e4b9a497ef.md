
# Audit + Improvement Plan: Tor & Privacy Hub

## Guiding principle
A privacy UI that *looks* on but *isn't* is worse than no UI. Every control must either (a) take effect and say so, (b) clearly require a restart and offer one, or (c) be disabled with an honest "not supported by the engine" label. No silent no‑ops, no fake progress, no dead toggles.

---

## P0 — Crash / data‑loss bugs (fix first)

### 1. `TorManager.kt` — `startActivity` from app context crashes
`tryStartOrbot()` and `requestNewCircuit()` call `context.startActivity(...)` with the **application** context (the manager is built with `appCtx`). Without `FLAG_ACTIVITY_NEW_TASK` this throws `AndroidRuntimeException` → crash on Tor auto‑connect at boot and on every "start Orbot".
- Add `Intent.FLAG_ACTIVITY_NEW_TASK` to every `startActivity` intent here.
- Replace the deprecated `getPackageInfo(ORBOT_PACKAGE, 0)` install check (breaks/ warns on API 33+) with `getLaunchIntentForPackage(ORBOT_PACKAGE) != null`.

### 2. `PrivacyHubScreen.kt:537` — "Clear Cookies" destroys everything
The Clear Cookies button calls `viewModel.rotateIdentity()`, which runs `storageController.clearData(ClearFlags.ALL)` (wipes logins, history, caches…) **and** requests a new circuit. A user tapping "Clear Cookies" loses all saved sessions.
- Add `BrowserViewModel.clearCookiesOnly()` → `clearData(ClearFlags.COOKIES | ClearFlags.DOM_STORAGES)` (no circuit change).
- Point the Clear Cookies button at it; fix its toast.

### 3. `BrowserViewModel.kt:3702` — `rotateIdentity()` guard is always true
`if (isAutoRotateIdentity || true)` makes the flag meaningless. Remove `|| true`; gate the auto behavior on the flag (see P2).

## P1 — The "nothing applies until restart" reality (core trust fix)

### 4. Introduce restart‑gating + a real Restart action
Gecko prefs only apply at `GeckoRuntime.create()`, and the runtime survives `Activity.recreate()` (it lives in the `ViewModel`). So a setting change needs a **process restart**.
- Add `BrowserViewModel.privacyRestartPending` (mutableState). Set it `true` inside every save‑function that only takes effect at startup: `saveDohEnabled/Uri`, `saveBlockQuic`, `saveDisableWebrtc`, `saveRandomizeUa`, `saveFingerprintProtection`, `saveProxyProvider` (proxy‑affecting values), `connectTor/disconnectTor`.
- Add `BrowserViewModel.restartApp(context)`: build the launch intent via `packageManager.getLaunchIntentForPackage(packageName)` with `FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_CLEAR_TASK`, start it, then `Process.killProcess(myPid())`.
- In `PrivacyHubScreen` (and the Settings PROXY & VPN block) render a top banner when `privacyRestartPending`: *"These changes apply after a restart."* + **Restart now** button.

### 5. Make Tor "Connected" honest
- `TorManager.simulateBootstrap()` fakes 10→100%. **Delete it.** After a successful SOCKS probe go straight `Connecting → Connected`; the UI shows an indeterminate spinner while `Connecting`. No invented percentages.
- When state becomes `Connected` but the Gecko proxy was just (re)written, also set `privacyRestartPending` and show *"Traffic will route through Tor after restart"* until the proxy was already active at boot. (We can detect "active at boot" by remembering the provider that was live when `getGeckoRuntime` last built the config.)

### 6. Custom Proxy / Tor‑over‑VPN currently route DIRECT
`geckoview-config.yaml` generation (`:1934`) and `updateGeckoProxyConfig()` (`:3746`) only handle `proxyProvider == "tor"`. The values `"custom_proxy"` and `"tor_over_vpn"` fall to the `else` → `network.proxy.type: 0` (DIRECT), so the browser never uses them even after restart.
- Define the proxy‑applying set as `{"tor", "tor_over_vpn", "custom_proxy"}`.
  - `custom_proxy` → host/port = `customSocksHost/customSocksPort` (require non‑blank host, else treat as direct + warn).
  - `tor` / `tor_over_vpn` → host = `customSocksHost` if set else `127.0.0.1`; port = bridge/default as today. (`tor_over_vpn` relies on a system VPN being up; we just route SOCKS the same way.)
- Apply the same logic in both the startup writer and `updateGeckoProxyConfig`.

## P1 — Dead / fake controls

### 7. Fingerprint Protection switch is dead (`PrivacyHubScreen.kt:576`)
`onCheckedChange = { /* TODO */ }`. Wire it: `viewModel.saveFingerprintProtection(context, it)` + mark restart pending.

### 8. Onion Routing switch is dead (`SettingsScreen.kt:1128`)
Hardcoded `checked = true`, empty handler. There is no pref for this — `.onion` works iff traffic is proxied to Tor. Convert to a **disabled** switch that reflects `torState is Connected`, with helper text *"Active while Tor is connected."*

### 9. Temporary Containers row is decorative (`PrivacyHubScreen.kt:579`)
No toggle, just "Requires restart". GeckoView exposes no per‑site container isolation via prefs. Replace with a **disabled** Switch + label *"Not available in this build"* (keeps the IA, stops the lie). (Real implementation = future work.)

### 10. DoT and plain Custom DNS use a non‑existent pref
`network.dns = <host>` is **not** a Gecko/Firefox pref, so both the DoT toggle and the Custom DNS toggle do nothing.
- Disable both switches with label *"Not supported by the engine yet"*. Keep the UI so it can be enabled later. (DoH stays — see #11.)

### 11. DoH bootstrap address is malformed (`:1948`)
`network.trr.bootstrapAddress` is set to the DoH **URL**; it expects an **IP**, so bootstrap is broken.
- Remove the `bootstrapAddress` line. Keep `network.trr.uri` + set `network.trr.mode: 2` (TRR with native fallback — chosen over mode 3 because a mis‑configured mode 3 with no bootstrap can black‑hole *all* DNS = total browsing failure, the worst setback). Document the trade‑off in a code comment.

### 12. QUIC pref name (`:1956`)
`network.quic.enabled` is unreliable across Gecko versions. Write **both** `network.http.http3.enabled` and `network.quic.enabled` = `!isBlockQuic` so the block actually lands.

## P2 — Identity features that don't match their label

### 13. "New Tor Circuit" button
Currently calls `rotateIdentity()` (full data wipe). Change to a real `BrowserViewModel.requestNewCircuit()` that only asks Orbot for a new circuit (local) or is **disabled** with explanation when on a custom proxy (we can't signal a remote SOCKS to rotate). No data wipe.

### 14. Auto‑Rotate Identity has no trigger
The toggle stores a flag but nothing acts on it. Implement a foreground‑only timer in `viewModelScope` (e.g. every 15 min while enabled) that calls `requestNewCircuit()` + `clearCookiesOnly()`. Cancel when disabled or backgrounded. (Keeps the feature real and bounded.)

---

## P2 — Information architecture: one source of truth for "Connection"

### 15. De‑duplicate Settings PROXY & VPN vs Privacy Hub
Today two screens pick the provider differently (3 chips vs 5 rows), Privacy Hub's rows **don't connect** anything (they only save a pref + toast), and live state is shown in Settings but not Hub.
- Make **Privacy Hub → Connection** the canonical, fully‑wired selector: each row shows live `torState`/`vpnState`, and selecting `tor`/`tor_over_vpn`/`wireguard` calls the same `connect…/disconnect…` used in Settings; selecting `custom_proxy` opens the dialog **and** on save calls a single `applyConnection("custom_proxy")`.
- Reduce the **Settings** PROXY & VPN block to *status + a "Manage in Privacy Hub" nav row* (keep the WireGuard import/edit card there since it's file‑heavy, but route provider choice through the Hub). This removes the conflicting 3‑vs‑5 mismatch.

---

## P2 — WireGuard is non‑functional (no VpnService)

### 16. `VpnManager`/WireGuard cannot work
The manifest declares **no** `VpnService` and there is no `VpnService.prepare()` consent flow, so `GoBackend.setState(...)` cannot bring up a tunnel — the "Connected" state is not a real VPN.
- This is adjacent to the requested scope but it's advertised in the same Connection UI. **Honest interim:** gate the WireGuard connect switch behind an *"Experimental — not yet available"* disabled state with explanation, so we stop implying a working VPN. Implementing a real `VpnService` wrapper is filed as separate future work (not in this change set).

## P3 — Localization backfill

### 17. ~30 new keys missing from all 8 locales
`privacy_hub_*`, `proxy_provider_*`, `tor_*`, `custom_proxy*`, `custom_dns*`, `doh_*`, `dot_*`, `block_quic*`, `disable_webrtc*`, `randomize_ua*`, `rotate_identity*`, `new_tor_circuit`, `clear_cookies`, `temp_containers*`, `fingerprint_protection*`, `tor_bootstrap`, `tor_over_vpn` exist **only** in `values/strings.xml`. Android falls back to English (no crash), so the "localized so it won't crash" claim is inaccurate.
- Add proper translations to `values-de/-es/-fr/-hi/-ja/-pt/-ru/-zh/strings.xml`. (Also add the few new strings introduced by this plan, e.g. restart banner, "not supported" labels.)
